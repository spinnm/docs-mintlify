Ein **Flow** beschreibt, wie ein Gespräch abläuft. Sie bauen ihn im **Flow-Editor** als **Zustandsgraph**: eine Landkarte aus Zuständen (States) und Übergängen zwischen ihnen.

## Der Flow-Editor

Der Flow-Editor ist eine grafische Oberfläche, in der Sie Zustände als Knoten anordnen und mit Verbindungen (Übergängen) verknüpfen. Sie können den Graphen frei anordnen, Zustände hinzufügen, bearbeiten und wieder entfernen.

## Zustandstypen

Jeder Zustand hat einen von drei Typen:

<CardGroup cols={3}>
  <Card title="REGULAR" icon="comments">
    Ein Gesprächszustand mit eigenen Anweisungen, erlaubten Tools und Übergängen.
  </Card>
  <Card title="FORWARD" icon="phone-arrow-up-right">
    Weiterleitung an eine externe Rufnummer (z. B. an einen Menschen). Terminaler Zustand.
  </Card>
  <Card title="HANGUP" icon="phone-slash">
    Beendet den Anruf. Terminaler Zustand.
  </Card>
</CardGroup>

## Übergänge und Bedingungen

Ein **REGULAR**-Zustand besitzt **Outputs** – benannte, sortierte Übergänge zu Folgezuständen. Jeder Output ist an eine **Bedingung** geknüpft:

- ein **Tool**, das im Zustand aufgerufen wurde,
- ein erwarteter **Response-Code** (das Ergebnis des Tools),
- optional **negiert** ("trifft *nicht* zu").

Beim Durchlaufen prüft der Agent die Outputs in ihrer Reihenfolge. Der erste passende Übergang bestimmt den Folgezustand.

<Note>
**Ohne Response-Code kein Übergang.** Löst ein Tool keinen deklarierten Response-Code aus, bleibt der Agent im aktuellen Zustand. So behalten Sie die Kontrolle über den Gesprächsverlauf.
</Note>

### Beispiel

```
[REGULAR: Begrüßung & Anliegen]
   ── classify → "termin"    →  [REGULAR: Termin buchen]
   ── classify → "sonstiges" →  [FORWARD: an Praxis]

[REGULAR: Termin buchen]
   ── book_appointment → "ok"        →  [HANGUP: Verabschiedung]
   ── book_appointment → "kein_slot" →  [REGULAR: Termin buchen]
```

## Tools im Zustand

Pro REGULAR-Zustand legen Sie fest, welche **Tools** der Agent dort verwenden darf. Es gibt zwei Arten:

- **`classify`** ✅ – eingebautes Tool, mit dem der Agent das Anliegen des Anrufers in von Ihnen definierte Kategorien einordnet. Die Kategorien werden zu Response-Codes für Ihre Übergänge.
- **Connector-Tools** 🚧 – fachliche Aktionen wie „Termin buchen" oder „Patient suchen", die über einen [Connector](/connectoren) an Ihr System gehen.

<Warning>
Die Anbindung der Connector-Tools an externe Systeme wird derzeit fertiggestellt (🚧). Sie können Flows mit diesen Tools bereits modellieren; die tatsächliche Ausführung gegen Ihr Fachsystem steht kurz bevor. Das eingebaute `classify` sowie Weiterleitung und Auflegen funktionieren vollständig.
</Warning>

## Zustands-Anweisungen und Slots

Jeder REGULAR-Zustand kann eigene **Anweisungen** tragen, die nur dort gelten (zusätzlich zu den [Basis-Instructions](/agenten-verwalten) des Agenten). Werte, die der Agent im Gespräch sammelt (z. B. ein genannter Name oder Wunschtermin), stehen als **Slots** im weiteren Verlauf zur Verfügung.

## Validierung

Der Editor prüft Ihren Flow laufend – etwa ob alle Zustände erreichbar sind und Übergänge gültig sind. Offene Punkte werden angezeigt, bevor Sie veröffentlichen. Zusätzlich können Sie Flows **importieren und exportieren**.

## Versionierung

<Steps>
  <Step title="Entwurf bearbeiten">
    Sie arbeiten immer auf einem bearbeitbaren **Entwurf (Draft)**.
  </Step>
  <Step title="Veröffentlichen">
    Beim Veröffentlichen wird der Entwurf validiert und als unveränderliche, nummerierte **Version** gespeichert.
  </Step>
  <Step title="Aktivieren">
    Sie setzen eine Version als **Live-Version**. Neue Anrufe nutzen sie ab sofort.
  </Step>
</Steps>

Frühere Versionen können Sie schreibgeschützt einsehen und bei Bedarf wieder als Entwurf öffnen.
