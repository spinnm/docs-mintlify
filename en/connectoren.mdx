So that an agent doesn't just provide information but **handles real transactions**, it calls **tools** in the [flow](/en/flows-bauen) – small, clearly defined actions such as "classify the request", "book appointment", or "look up balance". Where a tool comes from, and whether it talks to an external system, depends on its **category**.

## Three categories of tools

<CardGroup cols={3}>
  <Card title="Built-in tools" icon="wand-magic-sparkles" href="/en/system-tools">
    Platform-native tools available in **every agent without any configuration**. No external system, no credentials. Example: `classify`.
  </Card>
  <Card title="MCP servers" icon="server" href="/en/mcp-server">
    Connect **any MCP server**. The agent reads out its tools; you enable per agent which of them it may use.
  </Card>
  <Card title="Specialist-system connectors" icon="plug">
    Connect to your **practice or specialist software**. Provides business tools (e.g. appointment booking) and actually calls your system.
  </Card>
</CardGroup>

<Info>
This chapter describes how to **select and configure** integrations in the portal. The technical **implementation** of your own interface is out of scope for this handbook.
</Info>

## Specialist-system connectors

A **connector** links an agent to an external specialist system and provides it with the matching tools. Each tool is assigned to exactly **one** connector.

### Available connectors

In an agent's **Connectors** tab you see the available connector types (with description, number of supported tools, and the supported authentication methods) as well as your already active connectors.

| Connector | Purpose | Auth | Maturity |
|-----------|---------|------|----------|
| **planorg PVS (Principa)** | Appointment booking via the FHIR R4 interface of planorg's Principa practice-management system – look up patient, list practitioners/calendars, find free slots, book appointments. | Bearer token | ✅ live |
| **Debt management (demo)** | Demo connector: telephone balance inquiry and installment-plan agreement using fictitious sample data. | API key | ✅ demo |
| **Contract verification (demo)** | Demo connector: telephone confirmation call for a concluded contract using fictitious sample data. | API key | ✅ demo |
| **Standard connector (your own OpenAPI spec)** | Your system provides a standardized interface following the msg.Hello specification – maximum flexibility, no vendor lock-in. | API key | 🚧 being finalized |

<Note>
The **demo connectors** respond with hardcoded sample data and are handy for trying out a flow without a real specialist system. For production use, choose a specialist-system connector such as **planorg PVS** or an **[MCP server](/en/mcp-server)**.
</Note>

### Configuring a connector

<Steps>
  <Step title="Choose a connector type">
    Select the connector type that matches your system.
  </Step>
  <Step title="Enter the base URL">
    Enter the address (base URL) where your system provides the interface.
  </Step>
  <Step title="Enter the credentials">
    Enter the authentication (see below). Which fields appear depends on the selected method. Secret values are stored encrypted.
  </Step>
  <Step title="Enable tools">
    Enable the tools that the agent is allowed to use through this connector.
  </Step>
</Steps>

## Authentication

Specialist-system and MCP connectors support two authentication methods. Which one is available is determined by the connector type.

| Method | Field | How it is sent |
|--------|-------|----------------|
| **API key** | `API Key` | As a fixed key with every request (for MCP in the `X-API-Key` header). |
| **Bearer token** | `Bearer Token` | In the `Authorization: Bearer <token>` header. The token is passed through unchanged (e.g. a pre-issued JWT). |

<Note>
Your credentials are stored **encrypted**. Secret fields are no longer displayed in plain text in the portal after saving – when editing, leave the field empty to keep the stored value.
</Note>

## Example: appointment booking

The most mature use case is telephone **appointment booking** for healthcare via the **planorg PVS connector**. It provides tools to, among other things, identify patients, list practitioners and calendars, determine availability, and book appointments for both known and new patients. In your flow, you chain these tools together into a complete booking conversation.

<Tip>
After setting up an integration, you should thoroughly check the agent with a [test call](/en/agenten-testen) before going live.
</Tip>
