**Built-in tools** (also called *system tools*) are tools that msg.Hello ships itself. They are **automatically available in every agent**, need **no connector**, **no base URL**, and **no credentials**, and they talk to **no external system**. Their logic runs entirely on the platform.

<Info>
Because built-in tools are available without configuration, they do **not** appear in the connector selection. You enable them directly in the [flow](/en/flows-bauen) at the relevant state.
</Info>

## `classify` – classify the request

The central built-in tool is **`classify`**. With it, the agent assigns the caller's request to exactly **one** of the categories you defined. The chosen category becomes the **response code** on which your flow transitions branch.

<CardGroup cols={2}>
  <Card title="What it does" icon="tags">
    Picks the matching one from your categories (e.g. `appointment`, `prescription`, `other`) and returns it as a branching code.
  </Card>
  <Card title="When the agent calls it" icon="clock">
    Only once the category is unambiguous. When in doubt, the agent keeps asking rather than guessing.
  </Card>
</CardGroup>

### How to use it in the flow

<Steps>
  <Step title="Define categories">
    At a REGULAR state, define the allowed categories – these are the possible outcomes of the classification.
  </Step>
  <Step title="Link transitions">
    Connect each category to the target state the agent should switch to for that request.
  </Step>
  <Step title="Test">
    Use a [test call](/en/agenten-testen) to check that typical requests are classified correctly.
  </Step>
</Steps>

```
[REGULAR: Greeting & request]
   ── classify → "appointment" →  [REGULAR: Book appointment]
   ── classify → "other"       →  [FORWARD: to practice]
```

<Note>
`classify` is **fully live** (✅). It works locally and without side effects: no external call, no database, no stored slots.
</Note>

## Distinction: forwarding & hanging up

**Forwarding** to a human and **hanging up** are not tools but **state types** in the flow (`FORWARD` and `HANGUP`). They likewise work without any integration. See the [Building flows](/en/flows-bauen) chapter for details.

<Tip>
A useful starter agent combines only built-in capabilities: greet, recognize the request with `classify`, and forward when needed. You then build out business automation via [connectors](/en/connectoren) or [MCP servers](/en/mcp-server) step by step.
</Tip>
